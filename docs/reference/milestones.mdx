Milestones are **dependency-ordered** — each builds only on predecessors, with no circular dependencies.

| Milestone | Focus | Scope highlights |
|---|---|---|
| M0 | Bootstrap & Core | Application container, typed config loader, service provider DAG ordering, graceful shutdown |
| M1 | Routing & HTTP | axum router, route groups, domain-aware routing, middleware stack, typed extractors, HTTP client |
| M2 | ORM & Database | Query builder, `#[derive(Model)]`, migrations, seeders, factories, vector search |
| M3 | Auth, Middleware & Validation | Guards (JWT + session), `#[authorize]`, origin-aware CSRF, throttle, validation rules |
| M4 | Queue, Cache, Scheduling & Events | Typed jobs, queue routing, cache stores and locks, scheduler pause/resume, event dispatch |
| M5 | DX, CLI & Testing | `cargo artisan`, 17 generators, declarative attributes, testcontainers harness |
| M6 | Advanced | Broadcasting and real-time, search, filesystem, JSON:API, AI SDK, mail, presentation layers |

## Status

| Milestone | Status |
|---|---|
| M2 — ORM & Database | **Complete** |
| M0, M1, M3, M4, M5, M6 | **Partial** |

:::warning
The upstream [`docs/milestones.md`](https://github.com/rustasea/framework/blob/master/docs/milestones.md) is **authoritative** for the evidence-backed done/partial/missing recap. This page summarizes it and can lag behind.
:::

## Notable open items

- M0 — the scaffolded `AppServiceProvider` is still a no-op, and the config loader is not yet mounted during app boot.
- M1 — URL generation and implicit route-model binding remain open.
- M4 — the in-process `sync` driver keeps failed jobs in memory.
- M5 — generated controllers leave route registration manual; Docker-gated integration tests are opt-in.
- M6 — Gemini and Bedrock have no AI adapter; embeddings fall back to a deterministic stub.
